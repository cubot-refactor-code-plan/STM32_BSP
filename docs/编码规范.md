# CUBOT 编码风格规范

> 本文档以 `User/Bsp/bsp_uart.{hpp,cpp}` 为基准样板整理而成，是工程库统一遵循的标准。
> 格式类规则已固化在 `.clang-format` 中（保存时自动格式化），命名、注释、架构类规则需人工遵守。

---

## 1. 文件组织

| 规则 | 说明 |
|---|---|
| 文件名 | 全小写 + 下划线：`bsp_uart.hpp`、`protocol_uart.cpp` |
| C++ 头后缀 | `.hpp` |
| C++ 源后缀 | `.cpp` |
| C 调用 C++ 的转接头 | 用 `api_xxx.h`（纯 C 头，内含 `extern "C"`） |
| 正常 C++ 头 | `xxx_yyyy.hpp`（`xxx` 为 `bsp`/`alg`/`app` 等层级前缀） |
| 头文件保护 | `#ifndef __XXX_HPP__` + `#define` + 末尾 `#endif // __XXX_HPP__` |
| 文件说明块 | 只写在头文件最顶部；源文件最顶部不放任何说明，直接以 `#include` 开头 |

间接使用的头文件在行尾加 `// IWYU pragma: keep`，规避 clangd 误报。

## 2. 命名规范 User目录下

| 元素 | 规则 | 示例 |
|---|---|---|
| 类名 | 大驼峰 | `BspUart`、`DmImu`、`JC2804` |
| 结构体 | 大驼峰，不加 `_t` 后缀 | `PidConfig`、`PidInput`、`ImuData` |
| 方法 / 自由函数 | 小写蛇形| `init()`、`start_reception()`、`bsp_init()`、`calc()` |
| 私有成员变量 | `_` 前缀 + 小写蛇形 | `_huart`、`_rx_stream_buffer`、`_diff_mode` |
| 枚举类型 | `enum class` + 大驼峰 | `ReceiveMode`、`DiffMode` |
| 枚举值 | 全大写蛇形 | `SINGLE_BUFFER`、`DIFF_TARGET` |
| 宏 / 常量 | 全大写蛇形 | `MAX_INSTANCES`、`DATA_PACK_MAX_LENGTH` |
| 模板参数 | 全大写蛇形 | `BUFFER_SIZE`、`MSG_SIZE` |
| 全局实例 | 全小写蛇形 | `bsp_can1`、`bsp_uart1`、`imu_bmi088` |
| 类型别名 | 大驼峰（C 兼容 typedef） | `CanRxMsg`、`ProtocolFrame` |

例外：
  1. 构造函数 / 析构函数必须与类名（大驼峰）一致，如 `BspUart::BspUart()`
  2. 外部库（HAL / FreeRTOS 等 C 库）强制要求固定名称的回调，如 `HAL_FDCAN_RxFifo0Callback`、`vApplicationStackOverflowHook`、`__io_putchar`、`_write`
  3. CubeMX 生成的默认任务名（如 `StartDefaultTask`）保留原名，以便 CubeMX 重新生成时同名兼容

## 3. 注释规范（Doxygen）

> **@file 说明块只写在头文件的最顶部；源文件最顶部不放任何说明，直接以 `#include` 开头。**
> 文件说明、@details、@note、使用示例等全部收敛到头文件顶部；源文件内只保留函数/分区级注释。

```cpp
/**
 * @file bsp_uart.hpp
 * @author 名字
 * @brief 一句话说明这个文件是干什么的
 * @version 0.2
 * @date 日期
 *
 * @todo 待办事项
 *
 * @copyright Copyright (c) 2026
 *
 * @details 详细说明 / 使用示例
 *
 * @note 注意事项
 */
```

- **函数注释**：`@brief`（必须）+ `@param` + `@return` + `@note`；公共接口必须写全，私有函数可只写 `@brief` 或行注释
- **成员变量**：行尾 `///<` 注释
- **分区横幅**：`/* ==================== 分区名 ==================== */`
- **注释语言**：中文；描述"为什么"，而不是复述代码
- 未使用的参数写 `(void)arg;` 并注明

## 4. 类设计模式

1. **全局实例模式**：在 `xxx_cfg.cpp` 中实例化，`xxx_cfg.hpp` 中 `extern` 声明
2. **注册表模式**（目标，阶段 C 落地）：实例在 `init()` 时登记到静态表，中断回调查表分发，不再 if-else 判断句柄；当前 `bsp_can` / `bsp_uart` 的回调仍按句柄 if-else 分发给固定的全局实例
3. **模板实例化**：模板类定义在 `.hpp`，显式实例化放 `.cpp`（如 `template class BspUart<64>;`）
4. **HAL 中断回调**：统一放在对应 BSP 的 `.cpp` 中，用 `extern "C"` 包裹，通过句柄分发
5. **配置结构体统一模式（Config）**：所有类的初始化/构造参数一律收进类内的 `Config` 结构体（命名固定为 `Config`），构造函数 / `init()` 只接收 `const Config &`；禁止裸参数构造函数
6. **匿名结构体传参**：调用处传入 `Config` 时用匿名临时结构体，只按顺序传数据、不创建具名变量；`Config` 必须提供"参数顺序 = 字段顺序"的构造函数（带默认参数），以支持 C++11 下的 `Config{...}` 花括号列表初始化：
   ```cpp
   BspGpio power_5v({POWER_5V_GPIO_Port, POWER_5V_Pin});           // 构造函数传入
   key_user.init({KEY_GPIO_Port, KEY_Pin, true, 1U, 5U});          // init 传入
   BspUart<128> bsp_uart1({&huart1, true, 115200U});               // 句柄、是否启用发送、波特率（与 CubeMX 一致）
   ```
7. **构造函数只做赋值**：能在构造函数传入的就在构造函数传，不能在构造时完成的就在 `init()` 中传入；任何 FreeRTOS 相关操作或需要运行的函数（`xTaskCreate`、`xSemaphoreCreate*`、`snprintf`、`memset`、注册表注册等）一律移入 `init()`，构造函数中只允许成员赋值
8. **隐藏逻辑必须显式化**：如 `i_max == 0 → 跟随 out_max`，要写在构造函数里并注释

## 5. 分层架构

依赖方向（上层可用下层，禁止反向）：

```
App（应用层，api_xxx 转接）
 └─ Module
     └─ Protocol（协议层）
         └─ Device（设备层，单设备驱动）
             └─ Bsp（板载支持包，完全不考虑上层硬件细节）
```

- 每层文件前缀：`bsp_` / `device_`(或设备名) / `protocol_` / `alg_` / `api_`
- 跨层通信使用下一层暴露的全局实例，不直接操作 HAL

## 6. C/C++ 混编

- HAL / FreeRTOS 回调必须 `extern "C"`，防止名称修饰
- C 调 C++ 只通过 `api_xxx.h` 转接
- 任务函数若被 FreeRTOS 以 C 方式调用，需要 `extern "C"` 且参数为 `void *pvParameters`

## 7. 格式类规则（.clang-format 已固化）

- 2 空格缩进、Allman 大括号（换行）
- `*` `&` 靠右：`uint8_t *data`
- 连续赋值 / 声明对齐；行尾注释对齐
- 不限制行长（`ColumnLimit: 0`）
- 指针自动推导对齐（`DerivePointerAlignment`）

## 8. 断言与初始化失败

`configASSERT` 定义在 `Core/Inc/FreeRTOSConfig.h` 的 USER CODE 1 段：

```c
#define configASSERT( x ) if ((x) == 0) { fault_on_assert(__FILE__, __LINE__); }
```

失败时由 `User/Service/fault_record.cpp` 关中断、把种类 / 文件名 / 行号 / tick / IPSR / 任务名写进 `fault_record`（RAM_D1 的 `.noinit` 段，复位后保留），再停机：接着调试器时执行 `BKPT` 停在现场，没接就死循环。栈溢出与内存分配失败钩子（`freertos.c` 的 USER CODE 4 / 5）同样记录后停机。复位后用调试器 `print fault_record` 查看上一次故障。

- **初始化失败用断言**：句柄为空、RTOS 对象创建失败、外设起不来、配置与实物不符，都是“代码 / 配置写错了”，在 `bsp_init()` / `device_init()` 里**每条 `init()` 单独一行** `configASSERT(xxx.init() == Status::OK);`，记录里的行号直接指出是哪一路
- **运行期可恢复的失败返回 `Status`**：总线上的非法帧、超时、缓冲满、外部输入越界交给上层决策，不要断言（一帧噪声不应让整车停机）
- **注册阶段的失败**（`regist()` 等调用 `SysInitError()`）不会当场停机，由 `all_init()` 里的 `configASSERT(SysCompleteInit() == Status::OK)` 统一停机
- 任务入口先调 `SysFlagWaitRunning()`：等到运行位才放行；等到初始化失败位时任务自行退出，不会永久阻塞
- 中断里尽量不放断言：ISR 里只做最少校验，非法数据丢掉并计数即可
- `.ioc` 重新生成后检查 `STM32H723xG_flash.ld`：CubeMX 会用默认内容覆盖它，丢掉 `.dma_buffer` / `.noinit` 段，必须还原
