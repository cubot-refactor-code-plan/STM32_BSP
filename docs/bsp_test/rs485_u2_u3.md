# RS485 U2 ⇄ U3 测试记录

- 硬件：DM-MC02 板载两路 RS485（引脚图：485-1 = USART2 TX PD5 / RX PD6 / DE PD4；485-2 = USART3 TX PD8 / RX PD9 / DE PB14），
  A–A、B–B 对接，无额外终端电阻。DE 由 USART 硬件控制（CubeMX “Hardware Flow Control (RS485)”，`HAL_RS485Ex_Init(DE 高有效, DEAT=0, DEDT=0)`）。
- CubeMX 改动见 `changes.md` 第 1 节（USART2 加 DMA / 中断，USART3 改到 PD8/PD9）。
- 实例：`bsp_uart2` / `bsp_uart3` = `BspUart<128>`，115200（Config 与 CubeMX 一致）。
- 代码：`app/test/test_uart.cpp`（与 UART 用例共用收发器与帧解析）。

## 用例与方案

| 编号 | 测试项目 | 测试目的 | 测试方案 | 判据 |
| --- | --- | --- | --- | --- |
| R01a/b | 基本收发 | 半双工常规收发 | 单向 500 帧，1~100 字节，帧间 2 tick；两个方向各一次 | 无损 |
| R02 | 回波 | 收发器发送时是否同时接收（决定上层要不要滤自己的回波） | R01 期间统计发送端自己收到的本端帧数 | 记录硬件行为 |
| R03 | 请求-应答往返 | 半双工换向（DE 释放 → 对端回发）时序是否可靠 | U2 发 16 字节请求帧，U3 收到完整帧立即回 16 字节应答；循环 1000 次，每次等应答最多 20 ms；记录往返时间 | 1000 次全部成功、无 CRC 错 |
| R04 | 总线冲突 | 双方同时驱动总线后驱动能否自恢复 | 双方同时无间隔各发 50 帧；之后两个方向各发 200 帧复测（R04ra / R04rb） | 不挂死，复测无损 |
| R05 | 连续流 + 波特率扫描 | 高速下接收能力 | 每档 60 帧最大长度帧、无间隔，115200 / 1M / 2M / 4M（两端同改 BRR；收发器标称 10 Mbps） | 各档无损 |
| R07 | RS485 口上的 RX 故障注入 | U2 的中断号不在库 `uart_irqn()` 表里（静态检查发现），重建期间不屏蔽中断，看实际是否出问题 | U3→U2 传输中清 U2 的 `CR3.DMAR` 5 ms；之后复测 R07r | 恢复，复测无损 |
| R06 | 浸泡 | 长时间稳定性 | 交替方向每轮 200 帧，持续 `BSP_TEST_SOAK_MINUTES` 分钟 | 每轮无损 |

## 测试现象与结论

最终结果取第 10 轮（Debug）与第 12 轮（-O2）；物理插拔见 `README.md` P2。

| 编号 | 测试现象 | 结论 |
| --- | --- | --- |
| R01a/b | 两个方向各 500/500，约 11 KB/s（115200 理论 11.5 KB/s），各轮均无损 | 通过 |
| R02 | 两端发送时自己的接收都收到 0 帧 | 收发器发送时关接收（RE 随 DE），上层**不需要**滤自身回波 |
| R03 | 基线 1000 次往返 3 次超时、两侧各约 10 个垃圾字节（库的接收丢字节问题所致）；库修复后 Debug 1000/1000，往返 4.48~4.55 ms（两帧 24 字节 ≈ 4.2 ms 线上时间）；-O2 下 1000 次偶发 1 次超时，无 CRC 错、无驱动恢复计数 | 通过（Debug）；-O2 偶发 1/1000 超时**未定位**，怀疑与 UART 的 HAL_DMA_Abort 竞争同源（-O2 才出现），待循环 DMA 改造后复测 |
| R03b | 双方各加 200 µs 换向保护后：1000/1000 | 通过；硬件 DE（DEAT/DEDT=0）下即使不加保护时间也基本可靠，加了更稳 |
| R04 | 双方同时发：冲突期间 NE / FE 若干、两侧收到个别好帧；之后两个方向各 200/200，接收通道健康 | 通过，冲突后自恢复 |
| R05 | 基线 115200 / 1M 无损，**2M / 4M 各 60 帧坏 59 帧**（ORE）；最终四档全部无损，4 Mbps 约 95 KB/s（受测试接收任务 + 收发器限制） | 缺陷 → 与 UART 同（L4、L13） |
| R07 | U2 的中断号原不在库 `uart_irqn()` 表（静态检查发现），重建时不屏蔽中断；注入 ORE 后重建 1 次、丢 4~5 帧、复测 200/200，**未观察到实际故障** | L1 补上表项（USART2、USART6），属预防性修复 |
| R06 | -O2 浸泡 5 min：交替方向共 266 轮 × 200 帧，全部无损 | 通过 |

结论：RS485 口在库的 UART 驱动上工作正常，硬件 DE 时序可靠，冲突、断线（P2）均可自恢复。
