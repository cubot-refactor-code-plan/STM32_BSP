# CAN1 ⇄ CAN2 测试记录

- 硬件：DM-MC02 CAN1、CAN2 的 H–H、L–L 用短线对接，**没有 120 Ω 终端电阻**（用户确认）；USB 供电（CAN 收发器 5 V）。
- 配置：经典 CAN，1 Mbps（FDCAN 内核 96 MHz，NBRP 6，TSEG1 11，TSEG2 4），RX FIFO0 16 帧，TX FIFO 16 帧，自动重发开。
- 实例：`bsp_can1`、`bsp_can2`（`BspCan`），库默认配置（RX / 回退 / TX 队列各 8 帧，节点上限 50，心跳 5 ms，指令有效期 100 ms）。
- 代码：`app/test/test_can.cpp`。每条总线一个接收工作任务从 `receive()`（回退缓冲）取帧核对；序列帧 0x101（CAN1→CAN2）/ 0x102（CAN2→CAN1），
  data[0..3] = seq，data[4..7] = ~seq。
- 测试节点（`system_start()` 前注册）：CAN2 上 0x321（回调 OK）、0x322（回调返回 BUSY）、0x200（观察发送节点）；CAN1 上扩展帧 0x1ABCDE；
  CAN1 发送节点 0x200，division 4，槽位 0~3。

## 用例与方案

| 编号 | 测试项目 | 测试目的 | 测试方案 | 判据 |
| --- | --- | --- | --- | --- |
| C00 | 节点注册 | 前置 | 读 `test_can_init()` 注册结果 | 全部成功 |
| C01 | 基本收发 | 常规收发；无终端电阻是否可用 | CAN1→CAN2 1000 帧，再 CAN2→CAN1 1000 帧（每 4 帧让出 1 tick，FULL 时等待重试）；读 TEC / REC | 内容、顺序全对，错误计数 0 |
| C02 | 参数边界 | 文档约定 | `send(0x800)`、`send(id, nullptr)` 应 BAD_ARG；`send(0x000 / 0x7FF)` OK 且对端收到；`receive(nullptr)` BAD_ARG；无数据 TIMEOUT | 全部符合 |
| C03 | 接收节点分发 | 节点回调与回退缓冲的分工 | CAN1 各发 100 帧 0x321（回调 OK）/ 0x322（回调 BUSY）/ 0x323（未注册） | 0x321 只进回调；0x322 回调后进回退；0x323 进回退 |
| C04 | 发送节点 | 槽位聚合、心跳、指令有效期、注销 | 槽 0~3 已注册：(1) 每 1 ms 只填 0~2 → 只有心跳；(2) 注销槽 3 后填 0~2 → 每 ms 发；(3) 停填槽 1 → 测槽 1 被清零的时刻；(4) 全停 300 ms | (1) ≈200 帧/s；(2) ≈1000 帧/s；(3) ≈100 ms；(4) 数据全 0 |
| C05 | 非常规帧 | 扩展帧、DLC≠8、远程帧的处理 | CAN2 绕过 BspCan 直接发：扩展 0x1ABCDE ×10（有节点）、0x1ABCDF ×10（无节点）、0x150 DLC 0~7（每帧前先发一帧 0xEE 填充的 DLC 8，让栈上留下旧数据）、0x151 经典 DLC 9~15、远程帧 0x160 | 扩展帧正确分发；DLC<8 进回退且 DLC 之后为 0；DLC 9~15 计 `rx_len_drop`；远程帧不进应用 |
| C06a | 突发 | 发送缓冲满的行为 | CAN1 不等待连发 1000 次 `send()` | 有 FULL；所有返回 OK 的帧都送达 |
| C06b | 双向满载 | 接收路径容量 | CAN1、CAN2 同时尽量发 2 s | 所有 OK 的帧送达，无软件 / 硬件丢帧；结束后链路正常 |
| C07 | 无 ACK | 对端离线时的行为 | CAN2 置 INIT 300 ms，期间 CAN1 持续发；之后恢复 | CAN1 error-passive 但不 Bus-Off；积压帧在 CAN2 恢复后送达 |
| C08 | Bus-Off 恢复 | sys_task 的非阻塞恢复 | CAN1 轮换 4 种错误 NBRP 制造位错误，每次 300 ms 后恢复正确时序，等恢复后双向复测；目标 20 轮真实 BO | 每轮恢复、复测无损；CAN2 不 Bus-Off |
| C09 | 浸泡 | 长时间稳定性 | 双向序列帧 1 帧/ms + 发送节点持续写，`BSP_TEST_SOAK_MINUTES` 分钟 | 无丢失 |

## 测试现象与结论

最终结果取第 10 轮（Debug）与第 12 轮（-O2）；物理插拔见 `README.md` P3。

| 编号 | 测试现象 | 结论 |
| --- | --- | --- |
| C00 | 测试节点全部注册成功 | 通过 |
| C01 | 双向 1000/1000，内容、顺序全对，TEC / REC 0 | 通过；两节点短线、**无终端电阻**在 1 Mbps 下可用（正式整车仍应加 120 Ω） |
| C02 | 0x800 / nullptr → BAD_ARG；0x000、0x7FF 各收到 1 帧；receive(nullptr) BAD_ARG；无数据 TIMEOUT | 通过 |
| C03 | 0x321 只进回调（100 次，回退 0）；0x322 回调 100 次后进回退 100；0x323 进回退 100 | 通过，分发路径符合文档 |
| C04 | 只填槽 0~2（槽 3 已注册未填）：200 帧/s（只有心跳）；注销槽 3 后 999~1000 帧/s；停填槽 1 后 101 ms 槽 1 被清零；全停 300 ms 后数据全 0；unregist 返回 OK | 通过；注意“注册了但不填的槽位会让节点永远凑不齐、只剩 5 ms 心跳” |
| C05 | 扩展帧节点 10/10、未注册扩展帧进回退 10/10、DLC 9~15 计 `rx_len_drop` 7/7。基线：DLC < 8 的帧 **DLC 之后有旧数据**（8 帧中 1 帧）、**远程帧进入回退缓冲**；最终两项都为 0 | 缺陷 → L6（只拷 DLC 字节）、L7（硬件拒收远程帧，用户确认）修复 |
| C06a | 不等待连发 1000 次：FULL 约 935 次，接受的帧基线**丢 8 帧**（回退缓冲满，库里只置事件标志、没计数）；最终接受多少收多少 | 缺陷 → L8（新增 `rx_return_dropped` 计数）、L10（回退缓冲 8→16）修复 |
| C06b | 双向满载 2 s：基线 CAN1 收 16633 帧中 **`rx_dropped` 657（4%）**；最终 16627/16627 无丢失 | 缺陷 → L10 / L11（接收队列 8→16、每 tick 分发 8→16）修复。原写死 8 帧/ms < 1 Mbps 满载帧率（约 8~9 帧/ms） |
| C06c | CAN2 用 0x102 占满总线时，CAN1 最高优先级 0x050 在 200 ms 内送达 0~1/20 | **设计限制，未修改**：CAN1 发送节点 0x200 的周期帧（低于 0x102）发不出去，堆满硬件 TX（FIFO 模式按入队顺序发）和软件队列，高优先级帧进不去 |
| C06d | 运行中切到 TX 队列模式后重测：仍 0~3/20 | 同上：低优先级周期帧把 16 个硬件缓冲和 8 帧软件队列都占满。建议：发送节点对同一 ID 只保留最新值（替换而不排队），或总线负载规划上避免被更高优先级流量占满 |
| C06e | 队列模式下同 ID 1000 帧：基线 **CAN1 一帧都发不出**（卡住整个用例）；最终 1000/1000 且不乱序 | 缺陷 → L12 修复（库用 TFFL 判空位，队列模式下 TFFL 恒为 0；改用 TFQF） |
| C07 | CAN2 离线 300 ms：CAN1 TEC 到 128（error-passive），不 Bus-Off，send 积压后 FULL；CAN2 恢复后积压 20 帧全部送达，TEC 降到 93 | 通过 |
| C08 | 26 次注入得到 20 轮真实 Bus-Off，每轮由 sys_task 恢复、双向复测全部无损；累计 BO 与恢复成功次数相等；最长恢复 102 ms，最长“恢复时序到链路通”145 ms；CAN2 最高 REC 127，不 Bus-Off | 通过 |
| C09 | -O2 浸泡 5 min：双向各 300000 帧 + 发送节点持续写，无丢失、无乱序 | 通过 |

结论：CAN 驱动的收发、节点分发、Bus-Off 恢复可靠；发现并修复 6 处问题（L6~L8、L10~L12）；
总线被更高优先级流量占满时的“周期帧占满发送缓冲”属设计层面问题，已记录建议，未改。
