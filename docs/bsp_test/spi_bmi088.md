# SPI2 + 板载 BMI088 实机测试（2026-10-27 ~ 10-28）

对库新增的 `bsp/bsp_spi`（`BspSpi` / `BspSpiDevice`）与 `device/device_bmi088`（`DeviceBmi088`，输出 `service/imu_definition.hpp` 的 `ImuData`）
在 DM-MC02 上做基本功能、错误路径、故障注入、压力 / 浸泡测试，以及人工碰板 / 剧烈晃动对照。自动用例不需要跳线。测试代码 `app/test/test_spi_imu.cpp`，开关 `BSP_TEST_SUITE_SPI_IMU`。

## 安全约束：不开加热电阻

BMI088 旁的加热电阻由 **PB1 = TIM3_CH4（PWM）** 驱动，在本板上打开它容易损坏硬件。本次全程：

- 不改 TIM3 / PB1 的 CubeMX 配置（TIM3 已初始化、CCR4 = 0、从未启动），库和测试都不启动 TIM3、不写 PB1；
- 测试固件里有最高优先级的监视任务，每 10 ms 只读核对 `TIM3->CR1.CEN`、`TIM3->CCER.CC4E`、`TIM3->CCR4`、PB1 输入电平，
  任一非 0 就清 CC4E / CCR4 / CEN（只做关闭方向的写）并中止测试；每个用例结束时也核对一次（`v[9]`），调度器启动前再核对一次；
- 每次烧写后、每轮结束后用 OpenOCD 从外部读同样的寄存器。

结果：第 2~6 轮固件内共核对约 68 万次（129 058 / 224 407 / 187 906 / 92 141 / 44 282），外部 OpenOCD 核对 10 次，读到的全部是 `CR1 = 0x80`（只有 ARPE）、`CCER = 0`、`CCR4 = 0`、PB1 低电平；监视任务从未触发关断。

## 环境与配置

- 引脚：SPI2 SCK PB13 / MOSI PC1 / MISO PC2_C；ACC_CS PC0、GYRO_CS PC3_C；ACC_INT1 → PE10、GYRO_INT3 → PE12（EXTI 上升沿，优先级 5）。
- SPI2：主机、模式 3（CPOL 高 / CPHA 2edge）、8 bit、软件 NSS、预分频 32 ≈ 4.3 MHz。
- CubeMX 改动（`changes.md` 第 6 节）：SPI2_RX → DMA1_Stream0、SPI2_TX → DMA1_Stream7（挪用了没有使用的 UART8 的 DMA），SPI2 全局中断，`MasterKeepIOState = ENABLE`。
- 板级配置：`bsp_spi2({&hspi2, true, 16U})`（≥ 16 字节走 DMA），加速度计 `{…, 0x80, 1}`、陀螺仪 `{…, 0x80, 0}`；
  `imu_bmi088`：±2000 °/s、加速度计 1600 Hz、陀螺仪 2000 Hz / 230 Hz，数据就绪中断开；加速度计量程第 1~5 轮为 ±6 g，第 6 轮起改为 **±24 g**（见“剧烈晃动”一节）。
- 构建：Debug（-O0）与 RelWithDebInfo（-O2）各跑一轮；烧写用 EmberProbe `mcu-flash`，结果用 OpenOCD `read_memory` 读结果表（不停核）。

## 不合理帧：碰板对照实验（第 5 轮，已定论）

第 3 轮（无人值守）和第 3 轮固件重跑时，P01 / P02 出现了不合理帧（加速度模长不在 7~12 m/s²：5 / 201，167 / 187 帧）；第 4 轮 30 min 浸泡是 0。
为了定论，做了对照：-O2 固件只跑 P01（2 kHz 读 900 s），按秒记录不合理帧数、|gyro| 最大值、|acc| 范围；用户按时间表操作。

| 阶段 | 用户操作 | 不合理帧 | \|gyro\| > 0.2 rad/s 的秒数 | \|acc\| 范围 (m/s²) |
| --- | --- | --- | --- | --- |
| 第 0~299 秒 | 不碰 | **0** | 0 | 8.48 ~ 10.36 |
| 第 300~599 秒 | 依次：敲桌面、碰板边、拨 USB / 调试线、拿起放下、倾斜 | **3869** | 123 | 0.27 ~ 61.10 |
| 第 600~899 秒 | 不碰 | **0** | 0 | 9.52 ~ 9.89 |

- 不合理帧全部落在碰板那 5 分钟内（第 365~577 秒），前后两段不碰的 10 分钟里一帧都没有。
- 碰板阶段里，敲桌面那几秒（第 365~367、407~409 秒）角速度不大（< 0.1 rad/s）但 \|acc\| 有 5~15 m/s² 的冲击，所以“静止时的孤立不合理帧”记录里的 238 条也都是碰板造成的，不是读数出错（冲击短促、转动小，这个判据区分不开）。
- 整个过程中 SPI 层照常：180 万次 update 与中断数相同、0 失败，每 1000 帧 ID 核对 0 错。

**结论：不合理帧是板子被碰 / 震动造成的，不是驱动问题。** 之前几轮出现不合理帧时都无人值守；P01 / P02 的“不合理帧”判据假设板子静止，属于测试环境条件，
-O2 下 P01 / P02 的失败据此判为环境原因（第 4 轮 30 min 同样负载 0 不合理帧也一致）。

## 剧烈晃动：量程饱和与 ±24 g（第 6 轮）

碰板实验里每秒最大模长多次停在 58.9~61.1 m/s²，接近 ±6 g 的单轴满量程 58.84 m/s²，疑似饱和截断。为此：

- 库改动 L-BMI1：`DeviceBmi088::Config` 默认加速度计量程 ±6 g → **±24 g**（最大档）；`Bmi088RawData::saturated` 标出本帧顶到 32767 / -32768 的轴，
  `acc_saturation_count()` / `gyro_saturation_count()` 累计饱和帧；板级配置 `imu_bmi088` 改为 ±24 g（I03 回读期望 0x41 = 0x03）。
- 新用例 P06（人工）：同一颗芯片先 ±6 g、第 180 秒 `init()` 切到 ±24 g，用户在两段里同样剧烈地晃动（甩、抽、转、磕桌面）；按秒记录饱和帧、\|acc\| 范围、\|gyro\| 最大值。
  判据：update 0 失败、不漏帧、ID 核对正确、±24 g 段 0 饱和、陀螺仪 0 饱和、静止段 \|acc\| 在 7~12。

| 段 | 实际晃动 | \|acc\| 最大 | 加速度计饱和帧 | \|gyro\| 最大 | update / 失败 |
| --- | --- | --- | --- | --- | --- |
| ±6 g | 第 64~142 秒 | 95.7 m/s² | **25**（第 68、69、75、121 秒） | 30.9 rad/s | 全程 840 802 次 = 中断数，0 失败，ID 核对 0 错，接口失败 0 |
| ±24 g | 第 199~262 秒 | **162.6 m/s²（16.6 g）** | **0** | 33.8 rad/s | （同上） |

- **确认 ±6 g 在剧烈晃动下会饱和**，±24 g 在 16.6 g 的冲击下也不饱和；剧烈晃动下 SPI 通信 0 错误、不漏帧。
- P06 判为失败的唯一原因：第二段晃动在第 199 秒就开始了（约定第 240 秒），落进“静止段”，静止段判据失效；驱动相关判据全部满足。
- 陀螺仪：两段最大 30.9 / 33.8 rad/s（1934 °/s），离 BMI088 的最大量程 ±2000 °/s（34.9 rad/s）只差 3%；本轮 0 饱和，但更剧烈的转动可能顶满。
  ±2000 °/s 已是芯片上限，无法再放大；上层可用 `gyro_saturation_count()` / `saturated` 位识别被截断的帧。

## 锁超时：低优先级使用者自行传更长的 timeout_ms（已决定）

第 3 轮固件重跑时，P05 里最低优先级的 C 任务（读 ID 死循环）出了 1 次 TIMEOUT，单次操作 9.3 ms（默认 `SPI_TRANSFER_TIMEOUT_MS` = 10 ms）；第 4 轮 30 min 没有复现。
原因：FreeRTOS 互斥量释放时不直接交给等待者，高优先级任务紧接着又拿走，最低优先级任务等过了默认超时。这是公平性问题，不是传输错误。

用户决定：默认值不变，**允许低优先级使用者自己传更长的 `timeout_ms`**。改动（库 L-SPI2，未上板，按用户要求不再回归）：

- `bsp/bsp_spi.hpp` 文件说明里写明总线锁不按先来后到、低优先级使用者应传更长的 `timeout_ms`（如 50 ms 或 `portMAX_DELAY`）；`BspSpiDevice` 的接口本来都带 `timeout_ms`。
- `DeviceBmi088::update(uint32_t timeout_ms = SPI_TRANSFER_TIMEOUT_MS)`：原来没有超时参数，现在把它传给三次寄存器读取。Debug / -O2 编译 0 warning。

## 结论

- `BspSpi` / `BspSpiDevice`：寄存器读写约定（读标志位、读时无效字节）、轮询 / DMA 选择、零拷贝 / 弹跳缓冲与分段、总线锁、错误路径、DMA 超时恢复都按头文件约定工作；
  4 个不同优先级任务同时访问同一总线上的两颗芯片，Debug 20 min、-O2 30 min 浸泡 0 错误、0 数据不一致。
- `DeviceBmi088`：上电序列、配置回读、量程换算、数据就绪中断与任务通知正确；2 kHz 读取没有漏帧；碰板与剧烈晃动下 SPI 通信 0 错误、不漏帧。
- -O2 第 3 轮 P01 / P02 的不合理帧经碰板对照（第 5 轮）确认是板子被碰造成的，不是驱动问题。
- 剧烈晃动下 ±6 g 会饱和（读数被截断）→ 库默认改为 ±24 g，并提供饱和标志 / 计数；陀螺仪峰值 1934 °/s，接近芯片上限 ±2000 °/s。
- 低优先级任务在总线争用下可能等锁超过默认 10 ms → 默认值不变，由低优先级使用者自行传更长的 `timeout_ms`（`DeviceBmi088::update()` 已加参数）。
- 库改动：L-SPI1、L-BMI1、L-SPI2（见 `changes.md` 第 7 节）。
- 未覆盖：±24 g 默认配置下的全量自动用例（用户决定不再回归；±24 g 只在 I07 与 P06 里跑过）；L-SPI2 只编译未上板；D-Cache 开启（库假定关闭）；
  SPI 时钟 > 4.3 MHz；`BspSpi` 挂多路 SPI；BMI088 加热 / 温控（按约束不测）；运动状态下读数的绝对精度（只检查了饱和与范围）；
  `HAL_SPI_Abort` 在中断上下文里的行为（库只在任务里调用它）。
